# Workflow Reference Index
Updated: 2026-09-09

Read notes only when their trigger matches the current task. They supply technical/domain context, not independent execution authority. Do not preload all notes during init.

- [Working with documented systems](Workflow_References/when_working_with_documented_systems.md): before auditing, changing or documenting a described system.
- [Working with fragile system documentation](Workflow_References/when_working_with_fragile_system_documentation.md): when behavior depends on coupled owners or values.
- [Documentation format](../../Documentation_Format_README.md): when creating or maintaining documents.

For system work, first locate the relevant contract in [system descriptions](../../AI_Facing_Documentation/SYSTEMS_DESCRIPTIONS_FOR_AI/README.md) or the [shader library](../../AI_Facing_Documentation/SHADER_LIBRARY_FOR_AI/README.md). Read relevant FRAGILE_ descriptions fully. Implementation remains the source of truth for actual behavior; resolve discrepancies within approved scope.

For reusable tooling, consult the [ToolShed schema](../../ToolShed/Ledger/ToolShed_Format.md) and relevant catalog entries before rebuilding an existing capability. The supplied catalogs are empty. Add engine/language/environment-specific notes only as the new project needs them.
